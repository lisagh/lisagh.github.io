A transport control you can drive without a mouse.

My streaming work is confidential, so this is a public recreation of the problem underneath it: a seek bar is the hardest control in a player to get right, and almost every custom one ships broken for keyboard and screen-reader users. This one is real — tab into it and try the keys.

Decisions

The seek bar announces time, not a number

A bare role="slider" would read as “67” — sixty-seven of what? Every seek sets aria-valuetext to a spoken duration, so it reads “1 minute 23 seconds of 3 minutes 42 seconds”. aria-valuenow stays numeric underneath for anything that needs the raw value.

Arrow keys move 5 seconds, not 1 percent

The slider's range is time, so its step should be time. A percentage step makes the same keypress mean four seconds on a short clip and four minutes on a long one. J and L give a coarser 10-second jump for scanning, which is the pattern viewers already know.

One live region, on the status line

Announcements go to a single role="status" element, never to the thumb. Putting live text on the slider itself makes a screen reader read the value twice on every arrow press. Seek announcements are also debounced, so holding an arrow key produces one settled announcement instead of forty.

Hovering never steals focus

The scrub preview follows the pointer and is marked aria-hidden. It is a sighted-pointer affordance, so it adds nothing to the accessibility tree — a keyboard user already has the value spoken.

The shortcuts do not fight the page

Key handling is bound to the player, not to document. A global Space listener is the classic player bug: it hijacks the spacebar from every button and text field on the page. Here the keys only work once focus is inside the player.

State is readable without motion or colour

Play state has an icon, a label, and an announcement. Captions have aria-pressed rather than a colour change alone. Under prefers-reduced-motion the progress fill stops transitioning and the scene no longer cross-fades — the numbers still update.

What it does not do

There is no media file. A timer drives a simulated clock so the control logic is the whole artifact — dropping in a real <video> would mean replacing the clock with timeupdate and the seek handler with currentTime, and nothing else here would change.

It also does not attempt a full player: no quality selector, no cast, no picture-in-picture, no fullscreen. Those are real surfaces with their own problems; adding stubs for them would make this longer without making it better.
