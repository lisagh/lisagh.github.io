Embedded touchscreen UI for combine harvesters.

I designed UI features for the embedded touchscreen systems on John Deere combine harvesters, translating new hardware capabilities into updated interaction patterns and control layouts, and drove adoption of Deere’s Embedded Systems UX/UI standards across IT delivery teams worldwide.

Context

An embedded machine interface is not a consumer app. The operator is mid-task inside a harvester: loud, gloved, under time pressure in a season measured in days. A misread state costs real money.

What I Designed

Hardware capabilities arrived faster than the interface patterns that would expose them. My job was turning each one into a control an operator could use without retraining.

Interaction patterns

New capabilities, turned into controls and layouts.

HCI methods

HCI methods applied to workflows and interface states.

Hardware collaboration

UI decisions held against embedded-system constraints.

How I Decided

A standard only matters if delivery teams reach for it. Deere’s design documentation lived in SharePoint under SVN version control. I migrated it to Adobe XD and drove adoption across IT delivery teams worldwide — the harder half of the job, because a new tool only helps once the people on the other end actually open it.

Outcome

That migration improved engineering handoff efficiency by 50%.

This is where the habit I still work by started: treat the documented pattern as the product and the individual screen as an instance of it. The same instinct shows up now in component APIs — the reusable thing is the real deliverable, and a screen is just one of its outputs.
