Public reconstruction

The schedule framework, rebuilt in the open

The Paris Olympics shipped as its own page. Turning it into a feature that any league could use meant one component that takes a feed and lays itself out by time — which is what carries 1,700+ live events a year. HBO Max’s version is confidential; this is the same problem solved again with public data.

  • Position comes from time, not order. Every card is placed by its start and duration, so the same component renders a feed it has never seen.
  • One component, three feeds. Switching league swaps the data and nothing else — that is the difference between a page and a framework.
  • Keyboard and screen reader first. Arrow keys move along the rail, each card announces its time and state, and the now-line is decorative.

Interaction Challenges

Streaming interfaces need to feel fluid across device types, navigation patterns, content density, accessibility needs, and changing product requirements. My work focused on implementation details that users may not consciously notice but feel immediately when they are wrong.

  • Accounting for web, iOS, and Android needs during earlier React Native work, then focusing more deeply on browser behavior as part of the web team.
  • Supporting accessible focus, navigation, and readable UI states.
  • Preserving visual polish while working within shared component APIs.
  • Debugging production issues where technical defects surfaced as UX friction.

Engineering Decisions

I treated component implementation as a design tool: APIs needed to be clear enough for engineers to reuse, flexible enough for designers to evolve, and strict enough to protect consistency while keeping production standards intact.

I also drove AI-assisted engineering workflows across the team, including AI-generated unit tests and a CI failure summarization tool that streamlined testing and accelerated PR review. I frame this as engineering workflow experience, not as a claim that this case study represents an AI product.

Impact

The front-end work I owned for account, subscription, authentication, and payment flows — including region-specific payment methods — supports paid-content access for a 140M+ global subscriber base. Building shared UI components for the Home, Detail, and Schedule surfaces, optimizing performance, and resolving critical production defects contributed to an EFSR improvement from 97% to 98%.

Beyond the numbers: stronger design-engineering alignment, more reusable frontend patterns, and higher attention to interaction quality in production. Figures beyond these remain confidential.
