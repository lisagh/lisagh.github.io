Internal tools for experimentation, campaign workflows, and data visibility.

I built eBay’s internal campaign management platform from 0 to 1 as the primary front-end engineer for Marketing Tech, enabling operations teams to manage, monitor, and optimize merchant advertising workflows.

Public reconstruction

The table the whole tool hangs on

A campaign platform is mostly one screen: a lot of rows, a lot of numbers, and decisions made from both. Most of the work is in what that screen does when it is not showing a tidy list — which is why the state switcher below is the point, not a demo convenience. eBay’s tool is confidential; this is the same problem built again.

Campaign performance
Select Status

  • Four states, one component. Loading, empty and error are not screens someone else builds later — they ship with the table or the tool is broken the first time a query is slow.
  • Numbers line up. Tabular figures and right alignment, so a column can be compared by looking down it rather than reading every row.
  • Sorting is a button in a header. Real aria-sort, real keyboard focus, and the change announced — not a click handler on a div.

Public Note

Because this work is confidential, I focus on public-safe responsibilities, collaboration patterns, and UX engineering considerations rather than internal screenshots, datasets, metrics, or workflow specifics.

Context

Experimentation and operational workflows need interfaces that are fast to operate, easy to scan, and resilient to change. I worked with designers, PMs, backend engineers, and business stakeholders to deliver UI patterns that helped teams move through complex tasks more efficiently.

What I Built

Reusable UI Modules

Built the platform’s frontend modules from scratch so they could be adopted across multiple workflows and product surfaces.

Experimentation Flows

Supported rapid iteration for experimentation workflows, including complex states, validation, and configuration patterns.

Analytics Interfaces

Built data display patterns that helped teams scan operational signals without exposing sensitive data in this public case study.

Design Engineering Challenge

The challenge was not only to make tools functional, but to make dense operational workflows understandable. I focused on reducing friction in repeated tasks, clarifying information hierarchy, and building reusable patterns that could support future experiments without rebuilding from scratch.

Collaboration

I collaborated closely with design, product, and backend engineering, and mentored new engineers on reusable UI patterns. This helped create shared implementation habits that improved consistency across tools.

Impact

The work supported large-scale experimentation workflows and helped teams move faster with more consistent frontend patterns, clearer information displays, and reusable implementation foundations. Exact metrics and internal outcomes are omitted for confidentiality.
